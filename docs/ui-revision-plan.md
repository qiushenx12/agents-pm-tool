# 界面修改计划：以飞书多维表格体验为参照

日期：2026-09-07  
状态：P0–P2 已实施，结果见 [P0/P1 验收记录](ui-revision-acceptance.md) 和 [P2 验收记录](p2-acceptance.md)。

后续变更：2026-09-12 起侧栏只保留一个可折叠的「Agents PM Tool」模块承载项目列表（点击标题文字展开/收起，标题右侧加号用于新建项目），「工作空间」模块及其快捷筛选入口（全部任务/待验证/验收未通过）已移除；§3 P0-B 与 §3 P1-E 中的对应描述只代表当时方案。

## 1. 目标与依据

以飞书多维表格的工作区层级、紧凑信息密度、单元格操作和轻量反馈作为主要参照，覆盖浏览器任务表、新建任务、任务详情、项目选项管理以及桌面配置窗。

本轮围绕现有固定任务表展开。页面中的项目导航复用项目字段；快捷入口是同一张任务表的筛选预设。账号、协作权限、多表建模、公式、看板和日历等产品能力不列入本轮。

依据为当前工作区源代码及飞书官方说明。飞书区分数据表与视图，视图中的筛选、分组和排序配置具有各自的作用范围，可用来理解导航、数据与显示配置的层级关系：[多维表格的数据表和视图](https://www.feishu.cn/hc/zh-CN/articles/472603853615-%E5%A4%9A%E7%BB%B4%E8%A1%A8%E6%A0%BC%E7%9A%84%E6%95%B0%E6%8D%AE%E8%A1%A8%E5%92%8C%E8%A7%86%E5%9B%BE)。下文尺寸和颜色均为本项目建议初值，不是飞书官方规格。

初始方案审查时，Vite 依赖预构建出现 esbuild 解构转换错误。当时的差距判断基于源码；实施中已恢复预览并完成主要页面的实屏验证，结果见实施与验收记录。

## 2. 当前差距

| 位置 | 当前实现中的证据 | 对使用体验的影响 |
| --- | --- | --- |
| 页面框架 | `GridApp.vue` 只有标题、主题按钮、新建按钮、筛选栏、表格 | 项目、当前筛选范围与表格操作缺少分层 |
| 视觉规范 | `theme.css` 明确沿用 Apple 风格，主色为 `#007AFF`；按钮样式散落于共享样式、表格样式及配置窗 | 两个入口难以形成统一的组件语言 |
| 表格布局 | ID 在第一列并分配 190px；描述允许完整换行；所有九个字段默认显示 | 次要信息占用主要视线，长描述可能显著拉高行高 |
| 操作规则 | 普通行区域点击打开详情，描述点击立即编辑，项目/类型/状态为原生 select | 不同单元格的点击结果难预测，缺少统一选中态 |
| 筛选和列配置 | 已有多选筛选、URL 同步、关键词防抖、时间排序和列宽拖拽；列宽仅存组件内存 | 基础能力可复用，但条件可读性、恢复配置与入口一致性仍不足 |
| 浮层和反馈 | 项目选项管理使用居中遮罩；多处调用浏览器 alert/confirm；每行常驻删除符号 | 轻操作打断上下文，危险操作与日常操作争夺注意力 |
| 详情和新建 | 详情抽屉宽 420px，属性和描述为只读；附件视频预览复用 56px 缩略图样式；创建任务后逐个上传附件 | 详情中的继续操作不便，附件阅读空间不足；部分上传失败后的状态需要明确 |
| 数据刷新 | 编辑后重新获取列表，SSE 也触发列表和项目元数据刷新 | 需要检查重复请求、乱序响应以及刷新对编辑焦点和草稿的影响 |

## 3. 修改清单

### P0：建立统一视觉和页面结构

**A. 统一设计规范与基础组件**

- 建立背景、文字、分隔线、交互蓝、六种任务状态及明暗主题的语义色变量。浅色方案建议白色表格、浅灰导航区、低对比分隔线；交互蓝可先试 `#3370FF`。
- 建议初值：正文 13–14px、页面标题 18px、辅助文本 12px；间距使用 4/8/12/16/24px；控件高 28–32px；常规控件圆角 4–6px。
- 统一线性 SVG 图标，替换附件、主题、删除等位置的 emoji 和字符图标；图标按钮补充名称、提示和键盘焦点样式。
- 合并按钮、输入框、菜单、标签、提示、对话框的重复样式，明确普通、悬停、选中、聚焦、禁用、加载和错误状态。
- 浅色作为本轮主要设计验收基准，深色同步验证可读性和状态区分。

**B. 重做任务工作区骨架**

- 增加约 200px 的可折叠左栏：全部任务、项目列表、待验证等快捷筛选入口、项目管理。仅展示有实际行为的入口。
- 主区域依次为页面标题与当前范围、表格操作栏、已启用的筛选条件、表格、底部统计。
- 操作栏集中新建、筛选、排序、字段显示、行高及搜索；主题切换收纳至次要位置。
- 明确项目导航与手动项目筛选的关系：选择左侧项目时替换项目条件；手动修改项目条件后，左侧高亮随实际条件更新。
- 项目管理入口可发现，空项目列表给出创建项目动作，避免新用户进入无法选项目的新建表单。
- 保留表格为主的空间分配，导航在窄窗口可收起，横向滚动只发生在表格内部。

**C. 重做表格的阅读层级**

- 默认把任务描述放到主要阅读列；ID 提供复制入口并可通过字段设置显示。完整 ID 和所有原有字段在详情中可见。
- 增加固定宽度的行号/操作入口区域，冻结主列及表头；长描述默认截断，提供展开查看。
- 建议标准行高 36px，紧凑 32px、宽松 44px；编辑时使用浮层或明确的编辑区域，避免一条长内容打乱整表高度。
- 表头统一字段图标、名称及菜单；表头菜单负责已有排序、列显隐、列宽重置等功能。
- 项目、类型、状态、提交人的展示形式统一；原生 select 改为点击标签打开的定位菜单，菜单具备键盘操作和选中反馈。
- 删除收纳到行菜单或详情菜单，采用统一确认对话框；菜单入口在悬停、选中或键盘聚焦时可见。
- 列宽、列显隐和行高先按浏览器本地保存；筛选继续保持现有 URL 可恢复能力。

### P1：统一高频操作与反馈

**D. 明确单元格操作模型**

- 单击选中单元格；文本双击或 Enter 编辑；选项字段选中后再次点击或 Enter 打开菜单；详情由明确的展开按钮打开。
- 方向键移动选中位置，Tab/Shift+Tab 切换；多行文本 Enter 换行、Ctrl+Enter 提交，Esc 取消并恢复原值。
- 编辑器自动聚焦。统一失焦提交规则，确保 Esc 与失焦不会导致重复提交或误保存。
- 保存中、保存成功和失败状态就近显示；失败保留输入与重试入口。
- 按字段更新本地显示并以服务端返回结果校正；对请求乱序、同一任务连续修改及 SSE 重复刷新进行处理。
- 外部更新发生在当前编辑任务时，保留草稿并显示更新提示；列表刷新保持滚动位置与当前选中位置。

**E. 整理筛选和显示配置**

- 保留现有四类多选筛选及搜索防抖，把启用条件展示为可移除标签，提供清空全部和结果数量。
- 筛选、排序、字段设置统一为锚定按钮的浮层，支持点击外部关闭、Esc 关闭及关闭后的焦点恢复。
- 将已有两种时间排序集中到统一入口；更多字段排序作为后续能力评估，避免显示尚不可用的选项。
- “全部任务”“待验证”“验收未通过”等快捷方案映射到实际筛选条件，避免引入新的状态枚举。
- 区分无任务、筛选无结果、加载失败和连接中断，分别给出新建、清空筛选、重试等相关动作。

**F. 重做详情、新建与附件区域**

- 桌面详情侧栏建议从 560px 起试，支持调整宽度；宽屏打开后仍能定位当前表格记录，窄屏采用覆盖式面板。
- 详情按任务标识、可编辑属性、描述、附件组织，复用表格的字段编辑组件；提供上一条/下一条操作。
- 新建表单使用同一套控件，合理继承当前单一项目范围；无有效项目时提供创建项目引导。
- 附件支持拖拽、文件列表、上传进度或明确的处理中状态、失败重试与移除；图片和视频拥有独立预览空间。
- 明确“任务已创建、部分附件失败”的结果，重试只补传附件，避免重复创建任务。
- 新建成功后定位记录；若记录不符合当前筛选，提示创建成功及查看入口。
- 对话框和覆盖式抽屉补齐语义、焦点管理、Esc 行为及未提交草稿的关闭处理。

**G. 统一桌面配置窗**

- 使用与任务表一致的字体、图标、按钮、字段和反馈组件。
- 信息顺序调整为服务状态与打开任务表、常用设置、Agent 接入与高级配置。
- 采用清晰分组和对齐，减少层层卡片边框；保留监听范围等对用户选择有实际影响的说明。
- 保持标题栏拖动、最小化、关闭及托盘行为符合既有设置；保存、启动、重启、失败状态明确反馈。

### P2：按验证结果追加

已完成保存方案、列重排、分组、批量操作及服务端分页。性能实测和验证结果见 [P2 验收记录](p2-acceptance.md)；以下保留原计划条目。

- 自定义命名并保存筛选方案，作为现有固定任务表的显示偏好；先明确本地保存范围。
- 评估列重排、分组与批量操作。涉及新的服务端能力时另列接口任务，并明确部分成功的处理方式。
- 对 100、1000、2000 条任务测试渲染和操作耗时。当前有 2000 条渲染截断；如实际使用需要超过该范围，应提供可访问全部记录的分页或加载方式。
- 虚拟滚动依据测量结果引入；服务端分页涉及查询参数、总数及排序稳定性，独立估算，不能仅替换前端滚动组件。

## 4. 实施顺序与交付

| 轮次 | 工作 | 交付及通过条件 |
| --- | --- | --- |
| 第一轮：基准和规范 | 恢复预览；准备覆盖六种状态、长描述、长项目名和附件的独立样例；确定视觉规范 | 当前页面基准截图、主页面与详情方案、基础组件状态样例，能在真实尺寸下比较 |
| 第二轮：主体界面 | 完成 P0 的页面骨架、组件和表格阅读布局 | 可运行的主页面、筛选及字段浮层、两种主题；导航和入口均可操作 |
| 第三轮：完整流程 | 完成 P1 的编辑、筛选反馈、详情、新建、附件、配置窗 | 找到任务 → 修改 → 查看附件 → 新建 → 接收外部更新的流程连续可用 |
| 第四轮：验收修整 | 验证尺寸、缩放、键盘、异常、数据量及回归 | 截图对照、关键流程检查记录、遗留事项；决定是否启动 P2 |

工作量初估：P0、P1 与验收约 10–15 个工作日，按一名前端开发并复用现有后端估算；开发环境问题修复、后端扩展及 P2 在基准检查后单独校准。

## 5. 验收标准

- 在 1280×800、1440×900、1920×1080 下检查浅色和深色主题；Windows 125%/150% 缩放下无关键操作遮挡、浮层越界或文本裁切。
- 主页面、下拉菜单、详情、新建、配置窗使用相同组件规范；图标线宽、间距、边框和状态色一致。
- 长描述不撑开默认行高；主列和表头在相应滚动方向保持可见；列宽与显示偏好刷新后保留。
- 状态修改可在一次打开菜单、一次选择后完成；文本输入提交与取消符合统一规则，键盘焦点可见且可返回原入口。
- 编辑失败可保留并重试；SSE 更新不清空草稿、不跳动滚动位置；较旧请求不覆盖新的筛选结果。
- 无任务、无筛选结果、加载失败、断线、上传失败和保存失败均有可执行的下一步提示。
- 附件部分上传失败后不会产生重复任务；详情中的图片和视频可正常查看。
- 回归现有项目选项管理、九个任务字段、六种状态、筛选、排序、附件、主题及桌面窗口行为。
- 实施时运行项目构建与已有测试；针对编辑取消、请求乱序、部分上传失败等有行为风险的改动补充必要测试。纯样式以实屏检查为主。
