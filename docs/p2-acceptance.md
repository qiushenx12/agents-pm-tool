# P2 实施与验收记录

日期：2026-09-07

最终确认：2026-09-08，前端生产构建、23 项前端测试、21 项 Rust 测试和桌面开发版构建均通过。

## 已完成的功能

- **筛选方案**：命名保存、切换、更新、另存、重命名、删除；保存筛选、排序和分组。方案是独立快照，修改当前条件不会提前改写已保存内容。名称去重，存储失败会明确提示。
- **保存范围**：当前浏览器和访问地址（origin）的 localStorage；没有新增账号、云同步或跨设备共享。
- **列重排**：字段设置面板和表头支持拖拽；提供前移/后移按钮及表头菜单作为键盘可用的替代入口。任务描述保持第一列，列顺序、宽度和显隐均持久化；兼容旧版偏好数据。
- **分组**：按项目、状态、任务类型或提交人分组；可逐组展开或收起。分组统计来自完整筛选结果；跨页组标明本页条数与整组总数。
- **批量操作**：当前页可见记录全选、跨页保留选择；切换筛选条件时清除选择。每次最多 500 条，支持修改状态、任务类型、移动项目和删除任务。
- **部分失败**：逐条返回成功/失败，成功项从选择中移除，失败项保留名称、ID 和错误原因。重试仅发送失败 ID；删除和删除重试都有明确确认。
- **服务端分页**：提供 50/100/200 条每页、跳页、总数与页码纠正。数据库只查询当前页任务，浏览器不再获取全量任务后切片。按分组、用户排序及唯一 seq 稳定排序。
- **详情与定位**：单任务读取独立于筛选；新建后可按 ID 定位所在页；详情前后导航支持跨页。
- **接口兼容**：原有列表接口和 CLI 保持兼容；新增能力仅在网页路由提供，Agent 的权限范围保持原有约束。

## 接口

| 接口 | 行为 |
| --- | --- |
| GET /api/web/tasks/page | 返回 items、total、page、page_size、groups 和 anchor_found；支持原筛选参数及 group_by、anchor_id |
| GET /api/web/tasks/{id} | 获取单条任务，缺失时返回 404 |
| POST /api/web/tasks/batch | update/delete；逐项结果，最多 500 个输入 ID，重复 ID 去重处理 |
| GET /api/web/tasks | 保留原有数组响应，供兼容调用使用 |

每页接口默认 100 条、最多 200 条；非法页码和分组字段会被拒绝。末页记录减少时，服务端返回实际有效页码。

## 性能实测

数据：独立临时数据库，分别建立 100、1000、2000 条记录的样例项目。接口计时包含 HTTP 读取和 JSON 解析；每组预热一次，随后五次取中位数。

| 筛选记录数 | 原全量接口响应体 | 新分页响应体（100 条） | 原接口耗时中位数 | 新分页耗时中位数 |
| --- | ---: | ---: | ---: | ---: |
| 100 | 33,261 B | 33,340 B | 24.56 ms | 19.34 ms |
| 1000 | 335,511 B | 33,731 B | 39.17 ms | 21.38 ms |
| 2000 | 673,891 B | 33,831 B | 135.90 ms | 25.90 ms |

浏览器开发模式中，用 Vue nextTick 前后计时读取页面更新成本。以下是三组数据切换时记录的中位数；100 条组含一次 SSE 刷新，共四个样本，其他组各三个样本。

| 筛选记录数 | 实际任务 DOM 行数 | 取页到 DOM 更新完成 | DOM 更新部分 |
| --- | ---: | ---: | ---: |
| 100 | 100 | 37.1 ms | 27.3 ms |
| 1000 | 100 | 40.0 ms | 31.8 ms |
| 2000 | 100 | 39.4 ms | 26.7 ms |

2000 条时，响应体减少约 95%。此次采用有上限的服务端分页，任务 DOM 数量不随总记录数增长；实测未显示需要再加入虚拟滚动。这是本机开发环境的有限样本，不作为所有设备的性能保证，也不等同于完整绘制帧耗时。

重现接口基准：先启动独立临时数据库服务，再运行 `node scripts/benchmark-p2.mjs http://127.0.0.1:<测试端口>`。脚本会创建专用样例，输出计时及样例 ID 到 `data/p2-performance-fixtures.json`。本次生成的 3100 条性能记录在验证后已清理，其中一条用于模拟外部删除；原有预览样例保留。
