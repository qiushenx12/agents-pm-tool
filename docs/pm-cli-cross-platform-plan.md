# pm-cli 跨平台化与 skill 安装方式优化方案

> 状态：**已实施并验证**（2026-09-17）。本文保留为决策记录；实现清单与验证结果见文末 §8。

## 0. 一句话概括

把 `pm-cli` 从「随安装包分发的 Windows 专用 exe + 写进用户 PATH」改成「一个零依赖的 Node 单文件脚本」；把 skill 的交付方式从「下载 ZIP 手工解压」改成「网页直接写进目标目录」；顺带把所有相关文案统一到同一套口径。

## 1. 现状（问题）

**安装侧**
- 安装包通过 Tauri 的 externalBin 把 `pm-cli.exe` 一起装进应用目录，NSIS 安装钩子再把它所在的安装目录写进当前用户 PATH，另用注册表标记 `CliPathManaged` 记录「这个 PATH 项是我加的」，卸载时删除。
- 结果是：安装和卸载都要动用户 PATH，卸载不干净就留垃圾；用户机器上凭空多一个全局可执行的 `pm-cli`。

**skill 与连接发现**
- 主机：网页「我的 Agent 访问」可一键把 skill 装进已检测到的各前端目录 —— 但写进去的是 `SKILL.md` + `bin/pm-cli.exe`。
- 非主机用户：只能下载 ZIP，自己解压到自己前端目录。
- 连接发现里有一个先天矛盾：exe 按「自己所在目录下的 `data/runtime.json`」找运行信息，而 skill 装在前端目录里，这个文件天然不存在。所以主机用户被迫做目录联接（junction）才让 skill 里的 exe 找到应用；一旦 skill 被覆盖重装，联接就丢了，`pm-cli` 直接报「尚未配置连接」。

**平台**
- CLI 是 Rust 编译产物，Windows 与 macOS 需要各出一份二进制；当前只有 Windows 有。

## 2. 目标

1. 安装包只装 Agents PM Tool 本身：不分发 `pm-cli.exe`，不写用户 PATH，卸载不留任何 CLI 相关残留。
2. skill 的交付变成「网页直写目录」：主机一键装；非主机用户在网页上自己选目录，skill 按固定结构直接落到该目录，界面同时给出各前端的目录路径提示；不再以「下载压缩包再解压」作为主路径。
3. CLI 用一份跨平台的 Node 脚本实现，Windows 与 macOS 通用，**命令、参数、退出码、JSON 输出格式与现在完全一致**（Agent 侧的使用流程不用改）。
4. skill 文档、CLI 帮助、服务端帮助接口、doctor 排障文本、网页文案、README 全部重写并统一口径，不留任何旧说法（exe、PATH、解压 ZIP 等）。

## 3. 方案

### 3.1 CLI 载体：Node 单文件脚本

- 用一个 `pm-cli.mjs` 承载全部命令逻辑，**零第三方依赖**：HTTP 请求用 Node 内置能力，参数解析自己处理，不引入 npm 包，不需要联网安装任何东西。
- 前置条件只有一个：目标机器上有 Node 运行时（版本下限在实现时定死并在帮助里写明）。没有 Node 时，Agent 可退回「直接用 HTTP 调 `/api/agent/*`」，这条兜底路径现在就有，保留并向 Agent 提示。
- 调用方式保持"两个词"的体验：skill 里附一层极薄的包装（Windows 一个 `.cmd`，macOS/Linux 一个带执行位和 shebang 的短脚本），让 `pm-cli doctor` 这类写法照旧可用；底层都转发到 mjs。
- **但"能直接写 `pm-cli`"只在本机 PATH 里恰好有它时成立**，因此帮助与文档在第一次出现命令示例之前，必须先写清楚「先定位到 skill 目录，用其中的 pm-cli 调用」这一步（见 §6 口径）。
- 退出码沿用现有语义：`0` 成功、`2` 参数或鉴权失败、`3` 未配置或连不上。`--json` 输出结构不变。
- 帮助文本（总帮助、各子命令帮助、doctor 报告）从 Rust 迁到脚本内，与 SKILL.md 用同一份事实来源，避免两处说法漂移。

### 3.2 连接信息发现：跨平台 + 去掉目录联接

保持「越靠前越优先」的分层，并补上跨平台位置：

1. 环境变量 `PM_SERVER_URL` 与 `PM_AGENT_TOKEN`（必须成对，缺一个直接报错并指出缺哪个，这个行为保留）。**macOS 用户走的就是这条**（桌面应用暂时没有 mac 版，对他们而言就是远程连接）。
2. 用户配置文件。位置从现在的 `%APPDATA%` 硬编码改成跨平台固定的用户级位置，两端一致；旧路径仍可读，做兼容迁移。
3. **新增：应用发布的运行时指针。** 应用启动、端口变化、主机 token 重新生成时，把「当前端口 + 主机 token」写到用户级固定位置（不放应用安装目录）。pm-cli 从这一处零配置拿到动态端口 —— 这样 skill 装在任何目录都能直接工作，目录联接这套 workaround 彻底作废。该文件按当前用户私有权限存放，位置选择要照顾将来 mac 版的同一套语义。
4. 兼容路径：`PM_DATA_DIR` 指定的目录、应用安装目录下的 `data/runtime.json`（老用户的现状）。
5. 当前工作目录下的 `data/runtime.json`（开发调试场景）。

### 3.3 安装包与构建链瘦身

- Tauri 配置里去掉 sidecar（`externalBin`），产物只剩主程序。
- NSIS 钩子里「加 PATH / 删 PATH」两段整体退休，注册表标记项一并去掉。
- **新增一段过渡期清理（只做一次，之后删掉）**：新安装包在安装时主动清理旧环境残留 —— 旧版写进用户 PATH 的那一项（凭 `CliPathManaged` 标记识别，避免误删用户自己的 PATH 内容）、应用目录下的旧 `pm-cli.exe`。这段代码明确标注为过渡功能，下一版移除。
- 构建脚本里「release 编译 CLI → 复制 sidecar → 打 skill 压缩包」这条链路取消，改为「组织 skill 载荷」（把 SKILL.md、mjs、包装脚本、版本号装配成一份供服务端分发的内容）。
- Rust 侧只保留服务端分发 skill 需要的部分；仅为旧 CLI 存在的依赖（命令行解析库、HTTP 客户端库，以及不再需要的压缩库）随之清理。
- 移除 Rust 的 CLI 入口与相关源码。

### 3.4 skill 的目录结构（固定样式）

服务端只认这一种结构，前端目录下的落点是固定的：

```
<前端 skills 根目录>/
└─ pm-cli/
   ├─ SKILL.md          用法文档
   ├─ VERSION           版本号
   └─ bin/
      ├─ pm-cli.mjs     唯一实现
      ├─ pm-cli.cmd     Windows 便捷入口
      └─ pm-cli         macOS/Linux 便捷入口（可执行）
```

- 「是否已安装」的判定从「`bin/pm-cli.exe` 是否存在」改成「`bin/pm-cli.mjs` 是否存在」。
- 覆盖安装时先写新文件，再清掉同目录下遗留的旧 exe 和 `bin/data` 目录联接，避免新旧混用或继续指向旧位置。
- 版本号仍写 `VERSION`，doctor 里「skill 版本与 CLI 版本是否一致」的检查保留。

### 3.5 网页端安装体验

**主机（本机 loopback + 主机账号）**：保持一键安装。服务端本就能按已知前端目录直接落盘，卡片的状态、路径、版本、安装/更新、打开目录都保留，只是写入内容换成新结构。

**非主机用户**：服务端不碰对方的文件系统，改为在网页端完成。

- 主路径：一个「选择目录」按钮，用浏览器自身的目录选择能力把 skill 文件逐个写进用户选中的目录，不需要解压、不需要压缩包；写入前就能看到将要创建的结构。
- 界面同时给出**各前端的目录路径提示**，Windows 与 macOS 两种写法都列（按浏览器所在系统把对应的那种排在前面并高亮），支持一键复制，让用户知道该选哪个目录。
- 写入规则要明确、可预期：用户应当选「该前端的 skills 根目录」，程序在其中创建 `pm-cli` 子目录；如果用户选中的目录本身就叫 `pm-cli`，则直接写进去，避免出现 `pm-cli/pm-cli` 双层嵌套。这条规则在界面上写清楚。
- **硬约束（已核实）**：浏览器的目录选择与「另存为」对话框都**只在安全上下文（HTTPS 或 `localhost` / `127.0.0.1`）下可用**；局域网 `http://192.168.x.x:端口` 下会直接被浏览器拦掉。而普通下载又**由不得网页指定保存位置** —— 一律进浏览器下载目录，只有在用户自己打开了浏览器的「下载前询问保存位置」时才会弹框，这件事我们既控制不了也不该依赖。
- 所以非主机用户必须有一条不依赖目录选择的路径，具体形态见 §5。

### 3.6 跨平台边界（本轮做到哪一步）

- **本轮只保证 CLI 与 skill 在 macOS 上可用**，桌面应用仍只出 Windows 版；将来做 mac 桌面版时再单独处理。
- 换成 mjs 之后，macOS 可用性是**白拿的**：脚本不需要任何构建，拷过去就能跑。这正是本次改造最大的收益 —— 不再需要为 mac 单独编译一份二进制。
- 顺带说明：**mac 版的桌面应用确实必须在 mac 机器上构建**（Tauri/Rust 不支持交叉编译到 macOS，本机或 CI 的 mac 运行器都行）。但本轮不涉及，所以不需要 mac 机器。
- 为将来少返工，本轮先做两件与 mac 有关但不增加成本的事：① 路径提示里带上 macOS 写法；② 运行时指针选在跨平台语义一致的用户级位置，避免将来 mac 版又要挪一次。
- 已知的将来工作（本轮不做，仅登记）：mac 桌面版下「数据目录 = 应用同目录」的约定不成立（.app 包内不可写），要到那时统一改。

## 4. 已定的决策

| # | 决策 |
|---|---|
| 1 | 非主机用户的主路径 = 网页「选择目录」直写；**接受**其在局域网 HTTP 下不可用，必须配一条降级路径（形态待定，见 §5） |
| 2 | **接受** Node 运行时作为 CLI 的前置条件；无 Node 时退回直接用 HTTP 调接口 |
| 3 | 桌面应用要出 mac 版，但**本轮不处理**；本轮只保证 CLI 与 skill 在 mac 可用 |
| 4 | 旧环境残留只存在于当前机器：新安装包**主动清理一次**（旧 PATH 项 + 旧 exe），这段清理逻辑作为过渡功能，后续版本移除 |
| 5 | 文档与帮助里**统一写 `pm-cli`**，但首次给出命令示例之前，必须先说明「先找到 skill 里的 pm-cli 路径」 |
| 6 | 非主机用户的降级形态：**A + C 都做**（同一个自动落位的安装脚本，既可单独下载，也可用一行命令直接拉取执行）；**不再保留 ZIP 下载**，相关接口一并移除 |

## 5. 非主机用户的落地方式（已定：A + C）

因为目录选择在局域网 HTTP 下不可用、普通下载又无法指定位置，降级产物做成**「跑一次就自己落位」的安装脚本**——下载到哪儿都不重要，用户也不必自己组织目录结构。

- **A 单独下载安装脚本**：一个跨平台脚本，用户在目标机器上运行一次，脚本自动识别各前端目录（识别不到就接受一个指定目录参数），把 skill 按 §3.4 的结构写好，并打印结果与后续步骤。
- **C 网页给一行可复制命令**：直接拉取并执行同一个脚本，配合面板上已有的 token 鉴权，连下载和路径选择都不需要。
- 两者是**同一份产物**，只是获取方式不同；网页会话身份与 Agent token 身份各提供一个入口。
- **B（保留 ZIP）不保留**，原下载接口移除。

## 6. 文案统一：口径与排查清单

统一后的口径要点：**不再出现** exe、加入 PATH、解压 ZIP、手工排查 `data/runtime.json` 这些说法；**统一为**「skill 目录里的 mjs + 需要 Node；本机零配置，远程两条配置命令」。

关于命令写法（决策 5）的落地规则：任何文档或帮助，**先有一段"先定位路径"的说明**，例如指出 skill 装在哪个目录、`pm-cli` 在这个目录的 `bin` 下，然后才给出 `pm-cli xxx` 形式的示例；不要把 `pm-cli` 当成一个已经全局可用的命令直接甩示例。

需要逐个核对、重写或清理的位置：

**skill 与 CLI 自身**
- `pm-cli-skill/SKILL.md`：整篇重写（安装位置、如何先定位路径、连接方式、命令清单、Node 前置、排障）。
- CLI 的总帮助、各子命令帮助、doctor 报告文案（从 Rust 迁到 mjs 时一并统一）。

**服务端文案**
- `GET /api/agent/help` 的接口自述：开头介绍、`bootstrap` 三步、`if_pm_cli_missing`、命令清单里的 skill 获取项。
- 「我的 Agent 访问」接口返回的 `access_instructions`（主机版与远程版两套，都提到过 PATH、exe、ZIP）。
- skill 安装/打开的接口错误文案（如「未找到 pm-cli.exe，请先运行 npm run build:cli」），以及「一键打开目录仅支持 Windows」这类平台限制提示是否需要放宽。

**网页端文案**
- 「我的 Agent 访问」面板：卡片标题与说明、状态标签、按钮文字、「下载 ZIP」入口、非主机用户的提示块（现在是"下载 ZIP 后解压"）、新增的目录选择与路径提示区。
- 交给 Agent 的任务提示模板里出现的调用示例。

**仓库文档与脚本**
- README：安装与 PATH 段、skill 相关段、排障段、目录树、命令清单、构建命令。
- AGENTS.md：构建命令、目录职责说明。
- 开发脚本与构建脚本里的注释和提示文字。
- `docs/` 下的历史方案文档不追改（保留为历史记录），但要确保 README / AGENTS.md 与真实实现一致。

**仓库外**
- 你本机各 Agent 前端里已经装过的旧 skill、以及人为做的目录联接；升级后需要重新安装一次，这块的指引也要写在文档里。

## 7. 兼容与迁移

- 旧配置文件位置继续可读，不做硬切换。
- 已装的旧 skill 目录由新安装流程覆盖，并按 §3.4 清掉旧 exe 与遗留的 `bin/data` 联接。
- 旧 PATH 项按决策 4 由新安装包主动清理一次（过渡功能）。
- 本机人为建立的目录联接随 skill 重新安装一并消失，不再需要。
- 「我的 Agent 访问」面板签发的 token 机制不变，远程用户仍是「设置服务地址 + 设置 token」两条命令。

## 8. 实施结果（2026-09-17）

### 落地位置
- **新 CLI**：`pm-cli-skill/bin/pm-cli.mjs`（唯一实现）、`bin/pm-cli.cmd`（Windows 包装）、`bin/pm-cli`（macOS / Linux 包装）、`pm-cli-skill/VERSION`。
- **安装脚本模板**：`pm-cli-skill/installer.mjs`，由服务端注入文件清单后分发。
- **分发**（`src-tauri/src/server/api_skill.rs`）：`GET /api/agent/skill/payload`（清单，网页「选择目录」用）与 `GET /api/agent/skill/install.mjs`（自包含安装脚本），两者与 `/help` 同级免 token；主机一键安装仍走 `/api/web/local-skills/install`。
- **本机零配置**：`paths::user_config_dir/user_runtime_path` + `server::write_runtime_json` 同时写用户级运行信息，受 `CoreState::publish_runtime_pointer` 门控（只有桌面应用实例开启）。

### 与方案的差异
- 运行信息改成「应用写入用户级固定位置」，比方案里写的「指针文件 + 再读数据目录」更简单：少一次间接，且端口/token 变化时本来就要重写一次。
- 连接发现**不再包含当前工作目录**：实测发现那样会把命令连到无关实例上（在任意项目里恰好存在 `data/runtime.json` 时）。
- 增加了一条方案外的诊断：用户配置优先于本机自动发现，旧配置会盖住新机制，`doctor` 现在会点明端口不一致并给出修正命令。
- 安装脚本额外提供 `--list` / `--frontend` / `--all`，避免「装了多个前端时默认装哪儿」的歧义。

### 验证
- `cargo test --all-targets`：130 项全绿（含用 node 跑真实 `pm-cli.mjs` 的集成测试）。
- `npm test`：137 项全绿（新增 `tests/pm-cli.test.ts` 与面板的非主机写入用例）。
- 端到端：临时数据目录起无头服务 → 免 token 取清单与安装脚本 → 一行命令管道安装到临时 HOME → 装好的 CLI 零配置连通 → 建任务/推进状态/改优先级/列附件/下载附件全通，切「验收通过」被正确拒绝。
- 浏览器实测非主机面板：7 张卡片、路径提示随系统切换、可写目录与脚本降级都符合预期。
- 本机 5 个前端里已装过的旧 skill 已升级为新结构，旧 exe 与遗留的 `bin/data` 目录联接清理干净。
