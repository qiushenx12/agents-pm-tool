# 任务历史与撤销

## 数据与事务

v15 迁移新增 `task_operations`、`task_history`、`task_audit_context` 和快照视图/触发器。操作主体、来源、类型和时间由服务端提供；任务字段、关系两端、附件、级联父级状态均在同一业务事务中捕获初始与最终快照。无变化操作不留记录，失败回滚同步撤回记录。现有任务不补造升级之前的历史。

`history::record` 用保存点包住整个操作，任务 CRUD 与项目重命名的内部事务改为可嵌套保存点；批量接口仍返回逐项结果，仅成功项进入该次操作的历史。账号删除前保留负责人/提交账号名称。项目重命名更新历史的访问范围标记，保留快照中的历史项目名。

## 接口与权限

- `GET /api/web/tasks/{id}/history?before=<operation_id>`：倒序游标分页，每页最多 50 个操作。校验任务当前项目与历史项目访问范围；隐藏关联 ID 不返回。无权限时不返回历史内容。
- 可撤销写操作返回 `X-PM-Undo` 操作编号，0 表示没有实际变化；不修改原有任务 DTO。
- `POST /api/web/task-operations/{id}/undo`：仅本人 Web 操作可用，Agent 不能通过该入口绕过 Agent 权限。恢复值取服务端记录，不接受客户端提供旧值。每个受影响任务重新检查当前项目/字段/枚举/关联项目权限；逐字段比较操作后的值与当前值，冲突整笔拒绝。状态恢复按子任务先于父任务的顺序执行，仍调用既有状态校验与完成时间规则。撤销写入新的历史并标记原操作已撤销。
- SSE 继续只广播变化信号，历史内容通过有权限检查的查询加载。

## 前端行为

详情与历史分页切换保留编辑组件，历史支持空态、失败重试、游标加载及 SSE/本地编辑刷新。异步请求用序号防止切换任务后旧结果串入。

撤销栈仅保留本页面当前登录的最多 100 次字段、批量、关系、排序操作；按服务端操作编号排序，避免并发响应到达顺序影响撤销顺序。请求进行中禁止撤销，撤销进行中禁止提交新的任务修改。原生输入框、可编辑区域、组合输入和其它模态操作不触发全局撤销。新建/删除任务、附件操作清空撤销栈，仍使用原来的永久删除和文件清理语义。

## 验证

数据库测试覆盖新库/旧库升级、失败回滚和空修改；API 测试覆盖 Web/Agent 历史、附件、关系级联、可见性、项目重命名、重复撤销、并发冲突、批量原子性、权限变化及状态门槛；前端测试覆盖历史异步切换/分页/重试、撤销队列和原生快捷键边界。
