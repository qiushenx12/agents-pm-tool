## app 打开成表格而非设置窗（用户实测反馈）
- **现象**：release 打包后 app 窗口显示任务表格，不是设置界面。
- **根因**：`tauri.conf.json` 的 `app.windows[0]` 没写 `url` 字段，Tauri v2 默认加载 `frontendDist` 里的 `index.html`。dev 模式靠 `devUrl=http://127.0.0.1:5173/config.html` 掩盖了这个问题，release 就暴露。
- **修复**：`windows[0]` 加 `"url": "config.html"`。ConfigApp 功能本身是齐的（服务状态/数据目录/打开网页/端口/自启动/关窗行为/token 重生成都有）。
- **教训**：多入口 vite 项目（index.html 网页 + config.html 配置窗），Tauri 窗口必须显式 `url`，不能依赖默认；dev/ release 行为差异要分别验证。

## 实测三问题（打开网页/端口占用/顶栏拖拽）
- **端口 17890 被占**：前一天（9/2 16:40）调试截图用的 `serve.exe`（PID 31620）残留未杀，导致 app 启动顺延到 17891。已 Stop-Process 终止。**教训：调试用的 serve.exe 用完必须 taskkill，background task 超时 kills shell 但 rust 进程可能残留**。
- **顶栏无法拖拽**：`data-tauri-drag-region` HTML 属性在 Tauri v2 自绘标题栏里不可靠。照搬 cc-launcher `windowTitleBar.ts` 模式：手动 `@mousedown` → `appWindow.startDragging()`，用 closest() 排除 button/a/input 等交互元素；`@dblclick` → toggleMaximize。需补 capability `core:window:allow-start-dragging`。

## 「打开网页」Not allowed to open url（用户实测反馈）
- **现象**：点「打开网页」报 `Not allowed to open url http://127.0.0.1:17890`。
- **根因**：用了 `@tauri-apps/plugin-opener` 的 `openUrl()` + `opener:allow-open-url`，但 opener 插件对 URL 有 **scope 白名单机制**——光声明 allow 权限没配 scope 等于全拒。cc-launcher 用的是 `@tauri-apps/plugin-shell` 的 `open()` + `shell:allow-open`，无此坑。
- **修复**（与 cc-launcher 对齐）：前端 import 改 `@tauri-apps/plugin-shell` 的 `open as shellOpen`；Cargo.toml 加 `tauri-plugin-shell`；lib.rs 注册 `tauri_plugin_shell::init()`；capabilities `opener:allow-open-url` → `shell:allow-open`。opener 保留（托盘 open_web_page 仍用 OpenerExt，走的是 Rust 侧不经 capability 检查）。
- **教训**：Tauri 生态里同类插件（shell vs opener）权限模型差异大，照抄经项目验证的 cc-launcher 组合最稳；新插件引入后要实测一次完整链路。
- 回归：cargo 6 单测+8 集成、vue-tsc、vitest 6 全绿；bundle 含 `plugin:shell`；最新 exe 编入 `shell:allow-open`。
